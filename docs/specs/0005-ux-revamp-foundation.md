# 0005 UX revamp foundation (tokens, shell, shared components)

Port of the shared household UX from [urmade/homegrown-home#31](https://github.com/urmade/homegrown-home/pull/31), [#32](https://github.com/urmade/homegrown-home/pull/32), and the shared bits of [#34](https://github.com/urmade/homegrown-home/pull/34) / [#33](https://github.com/urmade/homegrown-home/pull/33). Designer steps 1–3 only: cool-grey tokens, AppShell, `@homegrown/ui` primitives. Instance module rebuilds (calendar, home cards, shopping/pantry adoption) stay in `homegrown-home`.

**i18n:** `resolveLocale()` is already member → household → English. `DEFAULT_LOCALE` stays `"en"` in `core/`. Harness `core.i18n.first-setup` picks English and asserts `html[lang=en]`. This PR does not hard-code German. New shell strings live in `apps/web/messages/{en,de}.json` because `check-i18n` binds `apps/web/app` + `apps/web/lib` to `core/messages` and does not read a web catalog. Copy is imported as JSON and read by property (`copy.more`), never `t("nav.more")`. Existing keys (`nav.settings`, `nav.admin`, module `title`) stay in their catalogs. `<html lang>` follows the resolved locale.

## Acceptance criteria

- [ux.theme.tokens] Light and dark CSS variables in `@homegrown/ui/tokens.css` match the designer shell table (`--hg-bg`, `--hg-surface`, `--hg-surface-raised`, `--hg-surface-sunken`, `--hg-border`, `--hg-border-strong`, `--hg-text`, `--hg-text-muted`, `--hg-text-subtle`, `--hg-primary` `#1F5AE0` light / `#7AA7FF` dark, `--hg-on-primary`, `--hg-primary-soft`, `--hg-danger`, `--hg-on-danger`, `--hg-success`, `--hg-warning`, `--hg-focus`, type/space/radius/shadow/motion). Beige (`#f7f6f1`, `#efede5`, `#3f7d4e` as accent) is gone from tokens, the web manifest (`background_color` / `theme_color`), and the generated icons. Tailwind `@theme` maps to `var(--hg-*)`. Legacy class names (`bg-bg`, `text-fg`, `text-fg-muted`, `bg-surface-muted`, `bg-accent`, `text-accent-fg`, `bg-warn`) still resolve so existing module pages keep working. `--hg-now` and calendar event triples are not added (no calendar in this repo). Empty/loading/error: n/a (tokens).
- [ux.theme.resolver] Token blocks are keyed only off `html[data-theme=light]` and `html[data-theme=dark]` — there is no `@media (prefers-color-scheme)` token override on `:root`. Preference is `system` (default) | `light` | `dark`, stored in `localStorage` (`hg-theme`). The head script always writes the **resolved** `light` or `dark` onto `data-theme` (so `system` + OS dark becomes `data-theme=dark`), plus `color-scheme` and a single `meta[name=theme-color]` (`#FFFFFF` light / `#161A21` dark), before first paint. `system` follows `prefers-color-scheme` live. `light`/`dark` override and survive reload. Missing, unreadable, or garbage `hg-theme` is treated as `system`. `localStorage` / `matchMedia` throws are caught so the script cannot block paint (fallback: `system`). Empty/loading/error: n/a.
- [ux.a1.bar] Breakpoints: tabs + app bar + app-bar `h1` only `<768`; icon rail + `PageHeader` `h1` at `768–1023` (no app bar); 232px sidebar + `PageHeader` `h1` and no app bar / no top nav at `≥1024` (harness 1280 and spec 1440). At 393×852 the app bar is one row: 52px when `safe-area-inset-top` is 0; title does not wrap (ellipsis). At `≥768` `PageHeader` is one line and 64px. One visible `h1` per view. Checked on `/`, `/more`, `/settings`, and each registered module route. `/setup` has no app bar, tabs, rail, or sidebar, and shows a visible Welcome title plus the language question at every width. Empty/loading/error: chrome always paints on non-setup routes.
- [ux.a2.overflow] `document.scrollingElement.scrollWidth <= innerWidth` on those routes at 393×852 and 1440×900, light and dark.
- [ux.a3.tabbar] At 393×852 a tab bar is visible on `/`, `/more`, and each registered module route with Start, then one tab per registered module in registry order, then More. Height ≥ 49px + `safe-area-inset-bottom`. Labels are 11px over 24px icons; active uses primary, inactive muted. Last content is not covered: main has bottom padding ≥ the tab stack. Hidden at 1440. Empty/loading/error: chrome always paints.
- [ux.a4.sidebar] At `≥1024` (1440 and harness 1280) a 232px left sidebar is visible (Start + registry modules + pinned Settings and Admin). Settings and Admin stay accessible by name (visible text on the sidebar; `aria-label` on the 768–1023 rail) so `core.i18n.*` still finds those links. The active item uses `primary-soft` / `primary`. There is no top nav. At 820 the rail is 72px. Empty/loading/error: chrome always paints (not on `/setup`).
- [ux.more] `/more` lists Appearance (System / Light / Dark), Settings, Admin, and App info. Admin is listed whenever today’s header listed it (always — there is no role gate). Settings and Admin remain reachable. Pushed screens (`/settings`, `/admin`, `/admin/logs`, `/admin/data-flow`, `/offline`) show a back chevron on mobile. Empty/loading/error: the list is static; App-info dialog closed vs open (title + close).
- [ux.a18.axe] axe-core: 0 serious or critical on `/`, `/more`, `/settings`, and each registered module route at 393×852 and 1440×900, light and dark.
- [ux.a19.hit] Interactive `button, a, input, [role=button]` in the shell chrome (`app-bar`, `app-tabs`, `app-sidebar`) plus on `/more` and `/settings` have a hit box ≥44×44 (padding included) at 393 and 1440. Module pages are not in this list (existing pantry/shopping controls stay as they are).
- [ux.a20.input] Visible `input, select, textarea` on `/settings` have computed `font-size >= 16px`.
- [ux.a21.keyboard] At 1440, Tab order on `/more` is logical; `:focus-visible` uses the 2px `--hg-focus` ring. The App-info dialog traps focus and Esc closes it, returning focus to the trigger.
- [ux.a22.theme] `system` follows the OS `colorScheme` live. `light` and `dark` override it and persist across reload. First paint `data-theme` equals the **resolved** mode (`light`/`dark` when stored, else OS when stored is `system` or missing). No beige flash.
- [ux.a24.border] A TextField/select border’s computed color vs its background contrast is ≥3:1 (border-strong) in light and dark.
- [ux.a25.hex] `rg '#[0-9a-fA-F]{3,6}' apps/*/src` matches no module source file (tokens live in `packages/ui`).
- [ux.a26.lang] `<html lang>` equals `resolveLocale()`. With household English, `lang="en"` and English shell copy. After the member picks German, `lang="de"` and shell copy is German (Start/Mehr/Darstellung/Einstellungen/Verwaltung). Visible UI strings come from catalogs, not literals. Web `en` and `de` catalogs have the same keys.
- [ux.ui.button] Existing `Button` (`primary | secondary | ghost`, already used on settings, setup, admin, modules) gets `whitespace-nowrap` and keeps disabled at 40% opacity + `aria-disabled`. This PR uses primary (save), secondary (App-info), ghost (dialog dismiss).
- [ux.ui.dialog] App-info on `/more` uses a native `<dialog>`: focus trap, Esc closes, focus returns to the trigger, accessible name. Overlay click closes. Below 768 it is bottom-anchored (raised surface, top radius-xl, grab handle, scrim), padded with `env(safe-area-inset-*)` on all four sides, max height `100dvh`, box ≤ `innerHeight` at 393. At `≥768` it is a centered 480px panel. Empty/loading/error: closed vs open.
- [ux.ui.fields] `TextField` / `Select` have a visible label (not placeholder-only), 44px control, 16px text, `border-strong`, `aria-invalid` + `aria-describedby` when error. Settings household + member locale become `Select` (two fields). `IconButton` requires `aria-label` and is 44×44 (back chevron on pushed routes + 768–1023 rail theme cycle). `TextField` accepts `inputRef`.
- [ux.ui.chrome] `Card` (home, settings, admin, `/more` — already), `SegmentedControl` (`role="tablist"` on `/more` Appearance and on the ≥1024 sidebar theme control), `Banner` (`Notice` alias; admin already), `EmptyState` (home + offline). `/more` rows are `Card` + `Link` / `Button`. Copy is always a prop (no literals in `packages/ui`). `AppBarProvider` / `useAppBar` is the extras slot the shell reads. SW reload stays on the existing `SwRegister`.
- [mobile.overflow] Every routed page including `/more` fits 393×852 and 375×667 without horizontal scroll (`documentElement` and `main`).
- [mobile.viewport-meta] The document viewport meta includes `width=device-width` and `viewport-fit=cover`.
- [mobile.safe-area] App bar uses `env(safe-area-inset-top)` (and left/right). Tab bar uses `env(safe-area-inset-bottom)` (and left/right). Main padding includes the tab stack.
- [mobile.header-single-row] At 375×667 and 393×852 the app bar is one 52px row when `safe-area-inset-top` is 0. Title ellipsis. No module/Settings/Admin links in the bar.
- [mobile.tab-bar] Under 768px the tab bar shows Start, one tab per registered module, and More; each ≥44px tall; labels truncate. Current section uses `aria-current="page"`: Start on `/`; a module tab when `pathname` is `/<name>` or starts with `/<name>/`; More on `/more`, `/settings`, `/admin` (and `/admin/…`), and `/offline`. At `md` (768px)+ the tab bar is hidden. Compiled Tailwind does not emit some utilities (`bg-primary-soft`, `text-primary`, `lg:not-sr-only`); those chrome classes are listed in `@source inline` or written as explicit CSS.
- [mobile.tap-targets] Visible shell controls (app-bar back, tab links) stay ≥44px tall.
- [mobile.input-font] Visible text inputs and native `<select>`s on `/settings` use a computed font-size of at least 16px.
- [mobile.dialog-fit] The App-info dialog is padded with `env(safe-area-inset-*)` on all four sides and capped at `100dvh` / `innerHeight` at 393.

UI states: shell chrome always paints (`ux.a1.bar`, `ux.a3.tabbar`, `ux.a4.sidebar`). `/more` App-info is closed (default) or open (`ux.more`, `ux.a21.keyboard`). Theme has no loading/error; a missing `localStorage` value is `system`. EmptyState (home, offline) and Banner/Notice (admin) stay the empty / error primitives.

Offline: registered module routes stay as declared (network-first; shopping writes still queue). `/more` and `/settings` are not declared offline routes; with the network off they show the existing offline notice. Theme preference is `localStorage` (works offline; no write queue). No new module writes.

## Plan

- Touched: `packages/ui` (tokens + primitives), `apps/web` (layout, `AppShell`, `/more`, manifest/meta/icons, `messages/{en,de}.json`, e2e), this spec. Existing module pages keep working via token aliases — no pantry/shopping-list rebuild, no calendar (this repo has none). No new module, table, dependency, or cross-module call. `AppNav` is deleted; `AppShell` replaces it.
- `core/` is not edited. New strings cannot go in `core/messages` without a harness+core PR; `apps/web/messages` is a shell catalog passed as props so `check-i18n` still sees no literals.
- Nav items come from `modules` (registry) + `getT(name)("title")`. Start and More are shell routes. Icons are a presentation map keyed by `manifest.name` with a generic fallback — a new module still appears without a shell edit. Admin visibility matches today’s header (always shown; no role API exists).
- Theme stays on the device (`localStorage`), not `core.settings`: it is personal and must apply before paint; a household row cannot run in the head script and would need `core/`.
- `AppShell` is a client child because `usePathname` (current tab) and theme listeners need the browser; the root layout stays a server component and passes already-translated labels (same reason as today’s `AppNav`).
- Shared components: restyle existing `Button` / `Input` / `Notice` / `Card` / `PageHeader` / `EmptyState` (already on settings, setup, admin, home, modules). `Input` stays exported as an alias of `TextField` so pantry, shopping-list, and admin-logs imports keep compiling. `Notice` stays an alias of `Banner`. New mounts with two callers each: `Select` (settings household + member; admin-logs level), `SegmentedControl` (`/more` Appearance and the ≥1024 sidebar theme control), `IconButton` (app-bar back on pushed routes; 768–1023 rail theme cycle). App-info uses a native `<dialog>` in `/more` (one overlay; no shared `Dialog` / `ListRow` until a second screen needs them). `/more` rows are `Card` + `Link` / `Button`. `PageHeader` hides its heading under 768; the mobile `h1` is always the app-bar title from `AppShell` (pathname + catalogs: Start / More / Settings / Admin / Offline, or the registered module `title`). Pages are not edited for titles.
- `AppBarProvider` / `useAppBar` is the extras slot inside `AppShell` (not a second shell). `/more` is the write caller: `MoreView` sets `extras.title` from the web catalog so the mobile `h1` is the page’s string, not a second hard-coded map entry. Other routes keep the AppShell pathname/catalog fallback. `extras.trailing` stays unused until a page here needs a bar action.
- Compiled Tailwind in this repo has not emitted some utilities used by the shell (`bg-primary-soft`, `text-primary`, `lg:not-sr-only`); chrome therefore lists them in `@source inline` or uses explicit CSS in `globals.css` (household #33 note, shared only).
- Failure modes of opening the PWA and moving between Home, registered modules, Settings, Admin, and theme:
  - Flash of beige or the opposite theme on load: head resolver reads `hg-theme` + `prefers-color-scheme` and sets resolved `data-theme` / `color-scheme` / `theme-color` before paint (`ux.theme.resolver`, `ux.a22.theme`).
  - OS is dark but the user picked Light, and the old `@media (prefers-color-scheme: dark)` block on `:root` still paints dark: that media block is removed; only `[data-theme]` sets tokens (`ux.theme.resolver`).
  - `localStorage` throws (private mode) or `hg-theme` is garbage: script is try/catch; invalid/missing → `system` (`ux.theme.resolver`).
  - OS theme changes while preference is `system` but the UI stays put: `matchMedia` listener rewrites resolved `data-theme` (`ux.theme.resolver`, `ux.a22.theme`).
  - Reload after Light/Dark snaps back to OS: persist `light`/`dark` in `localStorage` (`ux.a22.theme`).
  - Picking System/Light/Dark on `/more`, the ≥1024 sidebar `SegmentedControl`, or the 768–1023 rail cycle fails to apply immediately, or the three controls diverge: every control writes `hg-theme` and sets resolved `data-theme` / `color-scheme` / `theme-color` now; a same-tab event keeps all three aligned (`ux.a22.theme`).
  - Two `theme-color` metas (light + dark media) fight a manual pick: one meta, overwritten with the resolved hex (`ux.theme.resolver`).
  - Standalone splash / status bar stays beige or green: document `theme-color`, `manifest.theme_color` / `background_color`, and generated icons drop `#f7f6f1` / `#3f7d4e` (`ux.theme.tokens`, `ux.theme.resolver`).
  - Existing `import { Input }` in pantry, shopping-list, and admin-logs breaks after the field restyle: `Input` remains a `TextField` alias (`ux.ui.fields`).
  - Notch / home indicator cover the app bar or tabs: `viewport-fit=cover` (already) + `env(safe-area-inset-*)` on app bar and tab bar (`ux.a1.bar`, `ux.a3.tabbar`, `mobile.safe-area`).
  - Tab bar covers the last row or the SW toast: main padding-bottom ≥ tab stack; toast offset uses the same stack (`ux.a3.tabbar`).
  - Header wraps to two lines again: one 52px app bar, title ellipsis, no global links in the bar (`ux.a1.bar`, `ux.a2.overflow`).
  - Hiding `PageHeader` under 768 leaves no `h1` or an empty bar: `AppShell` always sets the mobile `h1` from pathname + catalogs / module `title`; `PageHeader` is the only `h1` at `≥768` (`ux.a1.bar`, `ux.a18.axe`).
  - `/setup` shows tabs so the user leaves before picking a language, or chrome+`requireSetup` loops: no shell chrome on `/setup`; heading stays a visible `h1` (not desktop-only `PageHeader`) (`ux.a1.bar`).
  - Harness 1280 hides Settings/Admin because the sidebar only exists at 1440: sidebar is `≥1024`; labels stay accessible names (`ux.a4.sidebar`).
  - Settings/Admin disappear and harness i18n / old bookmarks break: `/settings` and `/admin` stay; they are listed on `/more` and in the desktop sidebar; harness desktop viewport still sees the sidebar links (`ux.more`, `ux.a4.sidebar`).
  - Admin hidden for everyone or shown via a new invented role: keep today’s always-visible Admin (`ux.more`).
  - Module tabs hard-coded so a new module is invisible, or instance names (calendar) leak in: tabs/sidebar iterate `modules` (`ux.a3.tabbar`).
  - Unknown module has no icon and the rail overflows: generic fallback icon; labels truncate (`ux.a3.tabbar`, `ux.a4.sidebar`).
  - `/more` missing from overflow/axe: included in shell route lists (`ux.a2.overflow`, `ux.a18.axe`, `mobile.overflow`).
  - Pushed Settings/Admin have no back in standalone: leading chevron on non-tab routes (`ux.more`).
  - Desktop still has a wrapping top nav: sidebar only, no `body > header` nav at 1440 (`ux.a4.sidebar`).
  - Tablet shows both a 232px sidebar and a tab bar: 768–1023 is a 72px rail; tabs only under 768 (`ux.a3.tabbar`, `ux.a4.sidebar`).
  - Hit targets shrink below 44px or inputs zoom on iOS: 44px controls, 16px fields (`ux.a19.hit`, `ux.a20.input`, `mobile.tap-targets`).
  - Dialog Tab escapes to the page or Esc does nothing: trap + Esc + restore focus (`ux.a21.keyboard`, `ux.ui.dialog`).
  - Closed App-info stays painted, or Tab escapes, because `display` on `<dialog>` overrides the UA closed state and the modal trap: the dialog is a full-viewport transparent overlay and the sheet is an inner box (`ux.more`, `ux.a21.keyboard`, `ux.ui.dialog`).
  - Overlay/scrim click does nothing because `::backdrop` is not the dialog target: click on the transparent dialog (outside the sheet) closes; `closedby="any"` covers the UA backdrop (`ux.ui.dialog`).
  - App-info `Dialog` sits under the notch or home indicator: pad with `env(safe-area-inset-*)` and cap at `100dvh` (`ux.ui.dialog`, `mobile.dialog-fit`).
  - Reduced-motion users get overlay transforms: honour `prefers-reduced-motion` on the Dialog (`ux.ui.dialog`).
  - Placeholder-only fields fail labels / axe: TextField/Select require a label prop (`ux.ui.fields`, `ux.a18.axe`).
  - Module pages unreadable after token rename: keep `--color-fg` / `accent` / `surface-muted` aliases (`ux.theme.tokens`).
  - Hard-coded German breaks English e2e and `check-i18n`: catalogs + `resolveLocale`; no literals in ui (`ux.a26.lang`).
  - New `t("nav.more")` fails `check-i18n` because `core/messages` is read-only here, and a missing `de` key is silent: import JSON and use `copy.more`; same-keys test on the web catalogs (`ux.a26.lang`).
  - `check-core` fails because `core/` was edited: it is not (`ux.theme.tokens`).
  - Hex creeps into module src: aliases + no module restyle (`ux.a25.hex`).
  - Input border stays decorative `--hg-border` and fails 3:1: fields use `--hg-border-strong` (`ux.a24.border`).
  - Chrome utilities missing from the compiled sheet so the sidebar/tabs look unstyled: `@source inline` / explicit CSS (`mobile.tab-bar`).
  - `AppNav` left behind as dead code: file deleted; layout only mounts `AppShell` (`ux.a3.tabbar`).

## Assumptions

- Single household, no member-role API; Admin stays visible.
- No Konto/Abmelden — the app has no session logout.
- Home content stays the current module cards; the household “Heute” redesign is instance-only.
- This repo’s registered modules appear in the tab bar via the registry. No calendar route exists; the shell does not special-case one.
- English remains the unresolved-locale fallback (core + harness).
